# 야행국 夜行局

야행국 웹게임의 현재 작업 소스입니다. GitHub 저장소에 올려 Claude Code가 프런트엔드 코드를 검토하고 PC·모바일 UX/UI를 개선할 수 있도록 `index.html`로 구성했습니다.

## 현재 상태

- 현재 확보된 HTML 소스를 `index.html`로 복사했습니다.
- Supabase 연결 설정은 HTML 내부에 포함되어 있습니다. 브라우저용 publishable key만 사용해야 하며, `service_role` 키나 DB 비밀번호는 절대로 클라이언트에 넣지 마세요.
- 1차 UX/UI·안정성 개선이 반영되었습니다(아래 "변경 기록" 참고). 실제 계정 기반의 기능 테스트는 아직 수행되지 않았습니다.
- 기존 게임 기능을 분석한 뒤 수정은 별도 브랜치에서 진행하는 것을 권장합니다.

### 결정이 필요한 항목
- 프로필 "인물 저장"(이름·직책·특기·직업·소속)과 설정의 이름 변경은 클라이언트 직접 UPDATE라 권한 없음으로 실패한다. 직업·소속을 언제든 바꿀 수 있는지, 이름 변경 제한(중복·횟수)을 정한 뒤 서버 RPC로 옮겨야 한다.
- 구조 알림 읽음 처리도 클라이언트 직접 UPDATE라 실패한다(읽음 처리가 안 되어 알림이 반복될 수 있음). 본인 알림만 읽음 처리하는 RPC 추가가 필요하다(클라이언트 기능 확대이므로 승인 필요).
- 레거시 방(교류실) 코드가 남아 있으며, 관련 RPC는 의도적으로 막혀 있다.

## 실계정 테스트 절차 (아직 수행되지 않음)
준비
- 접속 주소: 정적 호스팅(GitHub Pages·Cloudflare Pages) 또는 로컬 서버(`npx serve .` 등). `file://`로 열면 인증 리디렉션이 동작하지 않을 수 있다.
- Supabase 대시보드 → Authentication → URL Configuration: Site URL과 Redirect URLs에 위 주소를 추가한다. (프로젝트: `https://bqywnmeryddwccrbomfe.supabase.co`)
- 계정 2개(A=파티장, B=동승자)를 서로 다른 브라우저 또는 시크릿 창에서 사용한다. 개발자 도구 Console·Network 탭을 열어 둔다.

순서와 기대 결과
1. 로그인·세션: A 로그인 → 새로고침 후에도 로그인 유지, 상단에 캐릭터 이름 표시. 로그아웃 후 Network에 RPC 반복 요청이 없어야 한다.
2. 데이터 불러오기: 프로필·인벤토리·지도 탭 이동 시 체력·정신·영력·소지품·현재 위치가 표시되고 Console 오류가 없어야 한다.
3. 이동·세부 지역: 세계지도에서 연결된 지역으로 이동(노정패 운임 1회 차감, 도착 시각 표시) → 도착 후 세부 지역 1~5단계 진입과 되돌아가기.
4. 탐색·탐사·채집: 세부 지역에서 탐색(파밍 스팟 발견) → 지점 채집 → 같은 지점 재채집 시 "재생성 전" 안내. 필드 채집은 12초 쿨다운.
5. 전투·조우: 지역 조우 → 공격·전술 행동 → 적 체력과 내 체력 변화 표시. 전투 중 이동 시도 시 거부.
6. 제작·인벤토리: 재료가 있는 제작법 1회 제작 → 재료 감소·결과물 증가가 인벤토리에 즉시 반영. 버튼 연타 시 1회만 처리.
7. 자율 활동: 시작 → 진행 중 재시작 거부 → 완료 후 수령(1회만) → 경험치·숙련도 반영.
8. 파티 동승: A가 파티 생성·B 초대 → 같은 지역에서 A가 동승 요청 → B 수락. A 노정패만 A 탈것 운임만큼 감소, B 노정패 변화 없음, 둘 다 이동 중 표시. B가 수락을 두 창에서 동시에 눌러도 1회만 출발.
9. 테마: 설정 → 화면 테마에서 프리셋 변경 → 새로고침 후 유지. 모바일(320·390px)에서 하단 탭·설정 메뉴·채팅 입력창 잘림 여부 확인.

## 로컬 미리보기

`index.html`을 브라우저에서 열어 정적 화면을 확인할 수 있습니다. 일부 Supabase 인증 및 데이터 기능은 브라우저 보안 정책, 인증 설정, Supabase 프로젝트 설정에 따라 로컬 파일 환경에서 정상 작동하지 않을 수 있습니다.

## 배포 전 확인

1. Supabase Auth의 허용 URL 및 리디렉션 URL 설정을 실제 배포 도메인에 맞춥니다.
2. DB의 RLS와 RPC 권한을 유지합니다. 클라이언트에서 비밀 키를 사용하지 않습니다.
3. 모바일과 PC에서 로그인, 캐릭터 상태, 이동, 전투, 거래, 파티 동승 등 주요 기능을 실제 계정으로 테스트합니다.
4. GitHub Pages 또는 Cloudflare Pages에 올리기 전에 현재 소스의 방 생성 UI, 폴링 주기, 반응형 문제를 검토합니다.
