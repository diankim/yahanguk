# 야행국 夜行局

야행국 웹게임 소스입니다. 정적 프런트엔드(`index.html` + `assets/`)와 Supabase 백엔드(`supabase/migrations/`)로 구성됩니다.

## 구조

- `index.html` — 빈 셸. 실제 화면은 ES 모듈이 그립니다.
- `assets/app.css` — 디자인 시스템(테마 토큰, PC 3열 · 모바일 상단 상태 띠/하단 탭 5개/채팅 시트).
- `assets/js/core.js` — Supabase 클라이언트(공개 publishable key만 사용), RPC 호출, 이름 사전, 공용 UI 도우미.
- `assets/js/app.js` — 로그인 → (최초 1회) 캐릭터 생성 → 게임 화면, 해시 라우터.
- `assets/js/hud.js` — 실시간 상태판(이동·자율 활동·전투·원정·전투불능).
- `assets/js/chat.js` — 전체·지역·세력·귓속말·파티 채팅.
- `assets/js/settings.js` — 헤더 메뉴: 프로필 · 테마(프리셋 12종·직접 설정) · 게임 설정(음향) · 알림.
- `assets/js/banner.js` — 이동 중 상단 알림 띠(남은 시간·도착 알림).
- `assets/js/views/` — 탭: 현장 · 지도 · 캐릭터 · 가방 · 일지 / 페이지: 동료 · 도움말 · 계정. `services.js`(상점·거래소·마구간), `expedition.js`(원정).

`service_role` 키나 DB 비밀번호는 절대로 클라이언트에 넣지 마세요.

## 로컬에서 보기

ES 모듈을 쓰므로 `file://`로 열면 동작하지 않습니다. 저장소 루트에서 정적 서버를 띄우세요.

```
python3 -m http.server 8765
# http://127.0.0.1:8765/
```

Cloudflare Pages에는 빌드 없이 저장소 루트를 그대로 배포하면 됩니다.

### 결정이 필요한 항목
- 프로필 "인물 저장"(이름·직책·특기·직업·소속)과 설정의 이름 변경은 클라이언트 직접 UPDATE라 권한 없음으로 실패한다. 직업·소속을 언제든 바꿀 수 있는지, 이름 변경 제한(중복·횟수)을 정한 뒤 서버 RPC로 옮겨야 한다.
- 구조 알림 읽음 처리도 클라이언트 직접 UPDATE라 실패한다(읽음 처리가 안 되어 알림이 반복될 수 있음). 본인 알림만 읽음 처리하는 RPC 추가가 필요하다(클라이언트 기능 확대이므로 승인 필요).
- 레거시 방(교류실) 코드가 남아 있으며, 관련 RPC는 의도적으로 막혀 있다.

## 실계정 테스트 절차 (아직 수행되지 않음)
준비
- 접속 주소: 정적 호스팅(GitHub Pages·Cloudflare Pages) 또는 로컬 서버(`npx serve .` 등). `file://`로 열면 인증 리디렉션이 동작하지 않을 수 있다.
- Supabase 대시보드 → Authentication → URL Configuration: Site URL과 Redirect URLs에 위 주소를 추가한다. (프로젝트: `https://bqywnmeryddwccrbomfe.supabase.co`)
- 계정 2개(A=파티장, B=동승자)를 서로 다른 브라우저 또는 시크릿 창에서 사용한다. 개발자 도구 Console·Network 탭을 열어 둔다.

순서와 기대 결과
1. 로그인·세션: A 로그인 → 새로고침 후에도 로그인 유지, 상단에 캐릭터 이름 표시. 로그아웃 후 Network에 RPC 반복 요청이 없어야 한다.
2. 데이터 불러오기: 프로필·인벤토리·지도 탭 이동 시 체력·정신·영력·소지품·현재 위치가 표시되고 Console 오류가 없어야 한다.
3. 이동·세부 지역: 세계지도에서 연결된 지역으로 이동(노정패 운임 1회 차감, 도착 시각 표시) → 도착 후 세부 지역 1~5단계 진입과 되돌아가기.
4. 탐색·탐사·채집: 세부 지역에서 탐색(파밍 스팟 발견) → 지점 채집 → 같은 지점 재채집 시 "재생성 전" 안내. 필드 채집은 12초 쿨다운.
5. 전투·조우: 지역 조우 → 공격·전술 행동 → 적 체력과 내 체력 변화 표시. 전투 중 이동 시도 시 거부.
6. 제작·인벤토리: 재료가 있는 제작법 1회 제작 → 재료 감소·결과물 증가가 인벤토리에 즉시 반영. 버튼 연타 시 1회만 처리.
7. 자율 활동: 시작 → 진행 중 재시작 거부 → 완료 후 수령(1회만) → 경험치·숙련도 반영.
8. 파티 동승: A가 파티 생성·B 초대 → 같은 지역에서 A가 동승 요청 → B 수락. A 노정패만 A 탈것 운임만큼 감소, B 노정패 변화 없음, 둘 다 이동 중 표시. B가 수락을 두 창에서 동시에 눌러도 1회만 출발.
9. 테마: 설정 → 화면 테마에서 프리셋 변경 → 새로고침 후 유지. 모바일(320·390px)에서 하단 탭·설정 메뉴·채팅 입력창 잘림 여부 확인.

## 로컬 미리보기

`index.html`을 브라우저에서 열어 정적 화면을 확인할 수 있습니다. 일부 Supabase 인증 및 데이터 기능은 브라우저 보안 정책, 인증 설정, Supabase 프로젝트 설정에 따라 로컬 파일 환경에서 정상 작동하지 않을 수 있습니다.

## 배포 전 확인

1. Supabase Auth의 허용 URL 및 리디렉션 URL 설정을 실제 배포 도메인에 맞춥니다.
2. DB의 RLS와 RPC 권한을 유지합니다. 클라이언트에서 비밀 키를 사용하지 않습니다.
3. 모바일과 PC에서 로그인, 캐릭터 상태, 이동, 전투, 거래, 파티 동승 등 주요 기능을 실제 계정으로 테스트합니다.
4. GitHub Pages 또는 Cloudflare Pages에 올리기 전에 현재 소스의 방 생성 UI, 폴링 주기, 반응형 문제를 검토합니다.

## 보안

`.env`, 서비스 역할 키, 데이터베이스 비밀번호, 개인 토큰은 이 저장소에 추가하지 마세요. 저장소는 기본적으로 Private로 만드는 것을 권장합니다.

## 서버 점검

1. **시작**: Supabase SQL Editor에서 `supabase/maintenance/start.sql`을 실행합니다. 게임 데이터·RPC(public 스키마)가 anon·authenticated·PUBLIC에게 닫혀, 게임 화면은 물론 공개 키로 API를 직접 불러도 `permission denied for schema public`으로 거절됩니다. 데이터는 건드리지 않습니다.
2. 화면은 진입할 때(`assets/js/boot.js`)와 게임 중 요청이 거절될 때 `maintenance.html`로 옮겨 갑니다. 앱 내부 경로(`#/map` 등)로 들어와도 같습니다.
3. **종료**: `supabase/maintenance/end.sql`을 실행하면 권한이 점검 전과 똑같이 돌아옵니다. 점검 페이지는 30초마다 서버를 확인하다가 열리면 원래 보던 화면으로 돌아갑니다.
4. 배포 없이 켜고 끌 수 있습니다. 계획 점검을 미리 알리고 싶으면 `maintenance.json`의 `active`를 `true`로 배포해도 됩니다.
5. 점검 페이지 안내는 `maintenance.json`에서 읽습니다(서버 차단으로 점검에 들어간 경우에도 보입니다): `message`(안내 문구), `until`(예상 종료, ISO 시각 예: `2026-10-28T03:00:00+09:00`), `notes`(이번 점검에서 하는 일 목록).
6. 점검 페이지를 다른 디자인으로 바꿀 때는 `assets/app.css`와 `assets/js/maintenance.js`를 불러오고 `data-maint-message`·`data-maint-checked`·`data-maint-next`·`data-maint-until`·`data-maint-notes`·`data-maint-state`·`data-maint-retry` 표식을 두면 저장된 테마와 자동 복귀가 그대로 동작합니다.
