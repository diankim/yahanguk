# 인수인계 2026-11-13 (이전 세션 → 새 세션)

이전 세션에서 운영 Supabase 연결 도구가 세션 시작 때 503(CLIENT_HTTP_NOT_IMPLEMENTED)으로 실패해 운영 DB에 SQL을 올릴 수 없었다. 그래서 아직 배포하지 않은 일을 모두 보관 브랜치에 올리고 새 세션에서 이어 간다. 새 세션은 이 문서를 처음부터 끝까지 읽고, 먼저 「0. 시작하자마자」를 한다.

## 0. 시작하자마자

1. Supabase 연결 확인: 연결 도구(mcp__Supabase__*)로 `select value from world_app_meta where key = 'db_version'`를 읽는다. 운영 값은 `20261113050000`(1.1.2)이어야 한다. 연결이 안 되면 다른 일을 하기 전에 바로 사용자에게 알린다(새 세션을 다시 열어야 함).
2. 보관 브랜치 가져오기(아래 표). 각 브랜치를 같은 이름의 로컬 브랜치로 받는다.
   - `git fetch origin keep/daily-1.1.2b keep/weekend-1.1.0 keep/bundle-2.1.0`
   - `git branch daily-1.1.2b origin/keep/daily-1.1.2b` (나머지도 같게)
3. `python3 tools/check/orphans.py bundle-2.1.0` — 1.1.2b 커밋 넷 정도만 「bundle에 없음」으로 나와야 정상(아래 2절).
4. 로컬 복제 DB(PostgreSQL 16)는 새 컨테이너에 없다. CLAUDE.md §17 「큰 SQL은 먼저 로컬 복제 DB에서」대로 운영 DB를 읽기 전용으로 받아 다시 만든다. 기준 DB = 지금 운영(1.1.2 배포 상태).

## 2. 지금 해야 할 일 — 1.1.2b 배포 (사용자 승인됨, 11/13)

배포 순서가 중요: **1.1.2b → (일요일) 2.0 → 2.1**. 일요일 묶음의 20261116170000이 1.1.2b가 만든 `world_grant_xp_got`를 쓴다.

1. 운영에서 되돌리는 시험(CLAUDE.md §17 11·11-1): `yh_deploy.buf`에 owner_inherit_begin.sql + `supabase/migrations/20261113060000_world_1_1_2b_fixes.sql` + owner_inherit_end.sql을 올리고 md5를 맞춘 뒤 사용자에게 ROLLBACK_TEST 실행을 부탁. 통과하면 실제 실행.
2. SQL이 들어간 뒤 `daily-1.1.2b`를 배포 브랜치에 push(빨리 감기 — 배포 머리 c18d412 위에 커밋만 얹음). version.json은 이미 `20261113-1.1.2b`·db `20261113060000`.
3. GM 전체 채팅 공지는 대규모 아님 → 공지 없음(패치노트 1.1.0 본문 끝 「## 1.1.2b」는 SQL에 들어 있음).
4. 배포 뒤 `daily-1.1.2b`를 `weekend-1.1.0`에, 그다음 `bundle-2.1.0`에 합친다(CLAUDE.md 12-1-1: 일일 묶음은 배포 뒤에만 합침). 합친 뒤 orphans.py 0건.
5. 배포 직후 사용자에게 화면 확인 부탁(이전 세션은 화면을 못 열었음): 현장 토벌 결과 경험치, 퀘스트 보고·의뢰 완료 문구, 귀허 대기실 거절 안내, 파티 토벌 결과.
6. 제보 답장: 66번은 2.0 배포 뒤 「고침」. 78②는 2.0 뒤 일.

### 1.1.2b 안에 든 것(사용자 결정 11/13)
- 구조대·요화 봉인 옮기는 곳: `world_safe_near(위치, 레벨)` — 같은 영역(territory_id) 안전지대 먼저, 없으면 가장 가까운 곳. 기존 지역 10곳의 행선지가 바뀜(회산 관문·서문 폐성벽 → 백등 야시장, 별바라기 언덕·옥문 협로·물시계 터 → 무극 관성대, 만인장·무명 고도 → 십삼문, 봉인고·옛 의금부 옥사 → 본부 객사, 폐쇄 사당 → 본부 정청).
- 현장 토벌 결과 xp: xp+24 → xp+12(실제 받는 양).
- 보상 문구 경험치 = 실제 들어간 양: `world_grant_xp_got(uid, xp)` → {levels, xp}. 퀘스트 보고·상시 의뢰·조사원 의뢰·봉연·귀허 정산. 만렙이면 0.
- 파티 토벌: 보상 받기용 guard는 막기 횟수에 안 셈(요괴 체력 0일 때), 동료 덤 yh.pf_n = 도망(fled)·이탈(gone) 뺀 참가자(쓰러진 사람 포함).
- 귀허: `world_gw_ready_check(uuid)` 한 곳에 조건·문구, `world_gw_ready`는 상태 검사 + 그것, `world_gw_invitable(uuid)`로 합류 가능한 파티원만 초대(없으면 바로 시작). fn_owner_field에 `world_busy_kind` 실행 권한 추가(없으면 늘 false였음).
- 새 도우미 권한은 yh_share(→ revoke public/anon/authenticated, fn_owner*·service_role·postgres에 grant) 뒤 yh_own(주인 fn_owner_field) 순서.
