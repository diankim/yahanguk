## 할 일
1. 시험 준비(사용자 승인 받음 — 「별채 없으면 진도 빼서 만들고, 다른 유저 출입 안 되게」). 운영 DB에 그대로 쓴다:
   - GM 별채 열기: `select public.world_housing_open('d3ce7dbb-9d58-4fa5-ade7-33d4e75bb1fe')`(서명은 먼저 pg_proc에서 확인 — 퀘스트 보상과 같은 6×6 + 기본 세트).
   - 두 별채 대문 닫기: `update public.world_housing set gate = 'closed' where owner_id in (GM, 윤해담)`.
   - 두 캐릭터 가방에 각각 `furn_pattern` 4 · `lumber` 8 · `lacquer` 4(2×1 가구 담기 + 두 개 짓기).
   - 넣기 전에 「무엇을 어떤 값으로」 채팅에 한 번 보여 주고 진행(CLAUDE.md 11-6). 시험 뒤 남은 물품·시험 가구·도안을 지울지는 사용자에게 묻는다.
2. 실제 화면 확인(운영 사이트 https://yahanguk.pages.dev, 시험 계정 둘). tools/check/screens.js가 YH_TEST_ID·YH_TEST_PW로 로그인한다 — 둘째 계정은 같은 방식으로 YH_TEST_ID2·YH_TEST_PW2를 쓰는 스크립트를 따로 만든다. 로그인 정보가 든 화면은 찍지 않고, 값은 로그·커밋·스크린샷에 남기지 않는다. 한 계정 한 곳 접속 규칙이 있으니 두 계정은 서로 다른 브라우저 문맥으로.
   - GM: 별채 머리 「가구 도안」 → 가구 그리기(2×1·탁자) → 담기 → 짓기(2개) → 곳간(「꺼내기」 없음) → 꾸미기에서 놓기·돌리기·저장 → 탁자 위에 소품 올리기 → 친구가 아니면 보내기 불가 확인.
   - 두 계정을 친구로 맺는 것은 운영 데이터 변경이라 사용자에게 먼저 묻는다. 맺으면 GM → 윤해담 사본 보내기 → 윤해담이 짓기·놓기.
   - 윤해담으로 GM 별채 구경: 대문을 닫았으므로 들어가지 못하는 것이 맞다. 제보 깃발 확인이 필요하면 잠깐 친구만(friends) 대문으로 바꿀지 사용자에게 묻는다.
   - 가방 「가구 그리기 도안」 → 「그리기」, 도움말 「가구 도안」, 휴대폰(iPhone 13) 화면 잘림.
   - 보고는 CLAUDE.md §17 「테스트 기준」 형식(코드·DB / 실제 기능 / 화면, 못 본 것은 미확인).
3. 확인 중 오류가 나오면 고칠 준비(로컬 커밋·복제 DB 시험)까지만 하고 승인 요청.

## 로그인 없이 확인하는 방법(참고)
이 세션은 실제 게임 앱을 복제 DB에 붙여 눌러 보는 시험대를 썼다(세션 작업 공간에만 있어 함께 넘어가지 않음). 방법: esm.sh의 supabase-js를 가짜 모듈로 바꿔 `rpc(name, args)`를 로컬 파이썬 서버로 보내고, 서버가 복제 DB에서 `set_config('request.jwt.claim.sub', 캐릭터)` + `set local role authenticated`로 그 함수를 부른다. `onAuthStateChange`는 INITIAL_SESSION을 바로 불러 줘야 앱이 뜬다. 복제 DB 만드는 법은 CLAUDE.md §17 「큰 SQL은 먼저 로컬 복제 DB에서」.
